# WS1 — Agent Runtime API v1 — Design

> **Status:** design approved section by section on 2026-09-26. Narrows the WS1 section of `2026-09-23-agent-store-developer-platform-and-sandbox-design.md` (§4.2 and the WS1 workstream). Where the two differ, this document wins. The buyer-facing run API in that section moves to a follow-up, **WS1b** (see §7).

## 1. Intent and scope

**Goal.** Agent code talks to the platform through `/runtime/v1/**` (spec §4.2), authenticated by its run token, and the platform records the run's trace itself instead of trusting the agent to report it. WS2 (data plane) and WS3 (LLM gateway) then plug their endpoints in behind WS1's auth, scope enforcement and step recording.

**In scope**
- New `runtime` package: `RuntimeAuthFilter`, `ScopeGuard`, `RunStepRecorder`, the rate limiter, problem+json errors and the controllers for `context`, `gates`, `usage`, `logs`, `heartbeat`, `complete`, `fail`, plus the `resources` and `llm/chat` controllers backed by interfaces (§3).
- `gate_request` table, agent-side gate endpoints, a buyer-side gate decision endpoint, reaper handling by `expires_at`.
- Run columns `mode`, `violation_count`, `input_json`; new `RunStepKind` values; `run_step.source`.
- Two additive manifest fields: `requiresApproval` on scopes and `timeoutMinutes` on gates.
- Per-run rate limiting (bucket4j on Redis).
- OpenAPI 3.1 contract generated by springdoc and checked in as `contracts/runtime-v1.yaml`, with a drift test.
- The legacy `/internal/agent-callback/**` stays behind a flag; `RunLauncher` injects both sets of environment variables; the `agentstore init` scaffold moves to `/runtime/v1`.
- Small frontend change: `RunStepResponse` gains `source`, and the run console labels the new step kinds and marks agent-reported steps.

**Out of scope** (with owner)
- WS1b: display IDs (`R-2291`), `terminal_reason`, `run_step.block`, `GET /runs/{id}/flow`, the grouped run list, `gate_request.estimated_units`, `POST /runtime/v1/network-events`.
- WS2 / WS3: the real `ResourceBackend` and `LlmBackend`; staged writes; `gate_request.preview`.
- WS14 / WS15: `gate_request.decided_via`, `eligible_approver_ids`.
- WS4: SDKs. WS6: sandbox runs, nullable `run.connection_id`, `initiated_by_org_id`, `simulated_charged`.
- Manifest v2 beyond the two fields above (`inputs`, `resources`, `llm`, UI text fields).
- Flagging an agent version for admin attention after violations. WS1 records the steps; the flag belongs to WS11 and the admin consoles.
- Removing the legacy callback (a later release).

**Success criteria**
1. A scripted fake agent, using only `/runtime/v1`, reads a resource, requests a gate, is approved, writes, reports usage and completes. The whole trace is platform-recorded.
2. A read of an undeclared resource returns `403 SCOPE_NOT_GRANTED` and appears in the trace as a `SCOPE_VIOLATION` step. In `PRODUCTION` the third violation ends the run.
3. With the legacy flag on, every existing legacy-callback test passes unchanged.
4. `contracts/runtime-v1.yaml` matches what the controllers generate; CI fails on drift.

## 2. Structure and authentication

**Package.** `com.agentstore.platform.runtime` holds the controllers, `RuntimeAuthFilter`, `ScopeGuard`, `RunStepRecorder`, the rate limiter and the error handling. State transitions stay in `RunLifecycleService` (`execution`); runtime controllers call it and never set run status themselves, which keeps the row-lock discipline from WS0. `AgentCallbackController` is unchanged.

**Security.** `SecurityConfig` gets a second `SecurityFilterChain`, ordered first and matching `/runtime/**`: stateless, no JWT filter, no API-key filter. `RuntimeAuthFilter`:
1. Reads the bearer token and finds the run by its SHA-256 hash.
2. Rejects with `401` for an unknown token, and `409 RUN_TERMINATED` for a terminal run or one past `deadline_at`.
3. Puts `RunPrincipal(runId, orgContext, mode, grantedScopes)` in the security context. `orgContext` comes from the run's connection.

The constant-time comparison in `RunTokenService` stays. The run id is no longer in the path; the token identifies the run. V25 adds an index on `run.callback_token_hash`, which does not exist today (V12 only renamed the column). It is deliberately **not unique**: production tokens are random 256-bit values, but existing tests give several runs the same fixed token string, and the legacy-callback tests must pass unchanged. Lookup uses `findFirstByCallbackTokenHash`.

**Rate limiting.** A bucket4j token bucket per run, backed by Redis, runs in the filter after authentication and answers `429 RATE_LIMITED` with `Retry-After`. `/logs` and `/llm/chat` have their own tighter buckets. Limits live in `application.yml`. If Redis is unreachable the limiter fails open and logs a warning: the buckets guard against abuse, and money is protected by the cost cap.

**Infrastructure.** Redis is added to `docker-compose.yml` as one container, `redis:7.2-alpine` (the last BSD-licensed release; self-hosted OSS, so it stays within the no-paid-vendors rule). The backend adds `io.lettuce:lettuce-core` and `com.bucket4j:bucket4j_jdk17-lettuce` and builds its own Lettuce `RedisClient` (created lazily, fast timeouts, commands rejected while disconnected) rather than using `spring-boot-starter-data-redis`: no auto-configuration, no health indicator that would turn `/actuator/health` red when Redis is down. `AbstractIntegrationTest` starts a shared Redis Testcontainer.

**Environment and the legacy flag.** `RunLauncher` injects `AGENTSTORE_API_URL`, `AGENTSTORE_RUN_TOKEN`, `AGENTSTORE_RUN_ID` and `AGENTSTORE_MODE`. While `agentstore.runtime.legacy-callback.enabled` is true (the default) it also injects `AGENT_CALLBACK_URL` and `AGENT_CALLBACK_TOKEN`. With the flag off, the legacy controller answers 404 and the launcher stops injecting those variables. The sandbox egress allowlist already contains the backend host. `/internal/runs/active-ids` belongs to the runner and does not move.

## 3. Endpoints, scope enforcement and the trace

All paths are under `/runtime/v1`, bearer run token.

| Method | Path | Notes |
|---|---|---|
| GET | `/context` | Run id, mode, agent version, `input_json`, granted scopes, limits (deadline, cost cap remaining). |
| GET | `/resources/{resource}`, `/resources/{resource}/records`, `/resources/{resource}/file` | READ scope; delegates to `ResourceBackend`. |
| POST | `/resources/{resource}/records` | WRITE scope; delegates to `ResourceBackend`, told whether the scope `requiresApproval`. |
| POST | `/gates` | §4. |
| GET | `/gates/{gateId}?wait=N` | §4. |
| POST | `/llm/chat` | Delegates to `LlmBackend`. |
| POST | `/usage` | `unit` must equal `costEnvelope.unitLabel`; reuses the WS0 cost logic. |
| POST | `/logs` | Batch, stored as `AGENT_LOG` steps with `source = AGENT`; size and rate limited. |
| POST | `/heartbeat` | Updates `last_heartbeat_at`. |
| POST | `/complete`, `/fail` | Through `RunLifecycleService`, so they release the wallet reservation and kill the sandbox. |

**ResourceBackend / LlmBackend.** Plain interfaces in the `runtime` package. Production wiring answers `501 NOT_IMPLEMENTED` until WS2 and WS3 provide implementations; authentication, `ScopeGuard` and the rate limit run first, so an undeclared resource is a `403` even now. The end-to-end test supplies in-memory implementations. WS2 and WS3 implement the interface and add no controllers.

**ScopeGuard** is the only place that decides allow or deny: `readResource`, `writeResource`, `gateAction`, `usageUnit`. Each checks the run's manifest. On a deny it records a `SCOPE_VIOLATION` step, increments `run.violation_count` and throws `403 SCOPE_NOT_GRANTED`. In `PRODUCTION` the third violation ends the run as `FAILED` through `RunLifecycleService`; in `SANDBOX` violations are reported and the run continues.

**RunStepRecorder** writes `run_step` rows with `source = PLATFORM | AGENT`, in the same transaction and under the same run lock as the state change. New kinds: `DATA_READ`, `DATA_WRITE`, `WRITE_STAGED`, `GATE_REQUESTED`, `GATE_DECIDED`, `LLM_CALL`, `USAGE`, `SCOPE_VIOLATION`, `AGENT_LOG`. The legacy kinds stay. `run_step.kind` widens to `VARCHAR(30)`.

**Errors.** RFC 7807 `application/problem+json` with a stable `code`: `SCOPE_NOT_GRANTED` (403), `RUN_TERMINATED` (409), `BUDGET_EXCEEDED`, `GATE_REJECTED`, `RATE_LIMITED` (429), `NOT_IMPLEMENTED` (501). An unsupported API version in `User-Agent` gets a 400 that says which versions are supported.

**Manifest additions.** The code has only the v1 manifest: `Scope(type, resource, description)` and gates as `(trigger, description)`. WS1 adds, backward-compatibly, `requiresApproval` on `Scope` (default false) and `timeoutMinutes` on `ApprovalGateDecl` (default 30). A gate `action` must equal a declared gate's `trigger` (at most 100 characters; the schema enforces it). **A scope is granted to a run when the manifest declares it and the buyer's connection lists its resource in `grantedScopes`** (buyers grant resource names, not READ/WRITE pairs). The `User-Agent` version convention is a `runtime-api/N` token; only `runtime-api/1` is accepted, and a request without the token is accepted too.

**Run columns (V25).** `mode VARCHAR(20) NOT NULL DEFAULT 'PRODUCTION'`, `violation_count INT NOT NULL DEFAULT 0`, `input_json JSONB NOT NULL DEFAULT '{}'`, the token-hash index (not unique, see §2), and `run_step.source VARCHAR(10) NOT NULL DEFAULT 'AGENT'`. `run.connection_id` stays NOT NULL until WS6.

## 4. Gates

**Table (V26).** `gate_request(id, run_id, action, summary, payload, affects_resources, status, decided_by_user_id, decision_note, created_at, decided_at, expires_at)`. `status` is `PENDING | APPROVED | REJECTED | EXPIRED`. `expires_at` = creation time + the gate's `timeoutMinutes`.

**Agent side**
- `POST /gates {action, summary, payload, affectsResources[]}` validates `action`, allows one open gate per run (a second returns `409`), writes the row and a `GATE_REQUESTED` step, and sets the run to `AWAITING_APPROVAL` (and `awaiting_since`) under the run lock. Returns `gateId` and `expiresAt`.
- `GET /gates/{gateId}?wait=N` waits at most 30 s, re-reading the row about once a second. Each read is its own short transaction, so no database connection is held while waiting. Virtual threads (`spring.threads.virtual.enabled=true`) keep the wait from tying up a platform thread. It returns `PENDING`, `APPROVED` or `REJECTED`. Redis pub/sub is not used to wake it sooner; a one-second delay on a human decision does not matter.

**Buyer side**
- New `POST /api/v1/runs/{id}/gates/{gateId}/decision {decision: APPROVE | REJECT, note}` with the same run-access authorization as today's approve and reject.
- The existing `/approve` and `/reject` delegate to the run's single pending gate. A run with no `gate_request` row (legacy callback) takes the existing status-flip path unchanged.
- Approve: gate `APPROVED`, `GATE_DECIDED` step, run back to `RUNNING`.
- Reject keeps today's behaviour: gate `REJECTED`, run `CANCELLED`, sandbox killed. An agent's poll may race the kill and never see `REJECTED`; a rejection ends the run.

**Reaper.** For a run with a gate row, the reaper expires it from `gate_request.expires_at`: gate `EXPIRED`, run `EXPIRED`. A run with no gate row keeps the current `awaiting_since` and `gateTimeout` rule.

## 5. Contract

`springdoc-openapi` generates OpenAPI 3.1 for `/runtime/v1/**` only. It is checked in as `contracts/runtime-v1.yaml`. A test fails when the generated document differs from the committed one, and its message says how to regenerate. WS4's SDKs and later CLI work build on this file.

## 6. Testing

- **ScopeGuard:** unit tests across scope type × resource × mode × violation count, including the 3-strike kill in `PRODUCTION` and report-only in `SANDBOX`.
- **Endpoint matrix:** every endpoint × (granted, not granted, terminal run, past deadline, bad or missing token).
- **Gates:** approve during a poll, reject during a poll, reaper expiry against a decision, and the legacy delegation path.
- **Rate limiting:** a Redis Testcontainer test that exceeds a bucket and gets `429`, and one showing a Redis outage lets requests through.
- **Legacy flag:** flag on, the old callback and environment variables behave as before and the existing legacy-callback tests pass unchanged; flag off, the old path is 404 and its variables are not injected.
- **End to end:** the acceptance test from §1 against `/runtime/v1`, with a scripted fake agent and in-memory `ResourceBackend` and `LlmBackend`.
- **Scaffold:** the `agentstore init` scaffold's tests move to the `/runtime/v1` `complete` call.

## 7. Follow-ups and ordering

- **WS1b** (buyer-facing run API): everything listed as out of scope for it in §1. It needs `gate_request` and `mode` from this workstream.
- **WS2 / WS3** implement `ResourceBackend` / `LlmBackend`.
- Removing the legacy callback and its environment variables is a later release, after the SDKs (WS4) stop depending on it.

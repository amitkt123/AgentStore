# WS10a Ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-sided wallet debit with a balanced double-entry ledger that splits every run charge into developer earnings and Karya's fee, deducts platform-LLM cost from the developer, supports prepaid and postpaid buyers, and shows it all on Billing, Earnings and admin screens.

**Architecture:** New `ledger_account`/`ledger_transaction`/`ledger_posting`/`ledger_account_balance` tables (V44) with a deferred trigger that rejects unbalanced transactions. `LedgerService.post` is the only writer; accounts are created lazily, and a buyer wallet's first account creation posts its existing balance as an opening `ADJUSTMENT` from `EXTERNAL`, so no data backfill is needed. `wallet.balance` and `ledger_entry` keep being written in the same transaction (dual-write) so existing readers keep working.

**Tech Stack:** Java 21, Spring Boot, JPA, Flyway, Postgres (Testcontainers), JUnit 5 + AssertJ + `TestRestTemplate`; Next.js 14 app router, TypeScript, CSS modules, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-21-ws10-money-in-and-out-design.md` §1 (Ledger), §4 where it touches the ledger. Read it first.

## Global Constraints

- Money is `BigDecimal` in Java and `NUMERIC(19,2)` in SQL. Never `double`/`float`. Rounding `RoundingMode.HALF_UP` to 2 places.
- Posting sign convention: positive raises the account's balance, negative lowers it. Every transaction's postings sum to exactly zero.
- `LedgerService.post` is the only code that inserts postings or changes `ledger_account_balance`.
- Lock order: the `wallet` row (`WalletRepository.findByOrgId`, `PESSIMISTIC_WRITE`) first, then `ledger_account_balance` rows in ascending `account_id`.
- Idempotency keys: run charge `usage:{usageEventId}`, LLM cost `llm:{runId}`, admin adjustment `adjustment:{clientRequestId}`, opening balance `opening:{orgId}`.
- Config (all under `agentstore.money`): `platform-fee-percent: 20`, `billing-mode: PREPAID`, `postpaid-default-credit-limit: 50000.00`, `tds.enabled: false`, `tds.rate: 0.001`, `tds.rate-no-pan: 0.05`, `gst-tcs.enabled: false`, `gst-tcs.rate: 0.01`.
- Roles are `BUYER_ADMIN`, `BUYER_APPROVER`, `DEVELOPER`, `ADMIN` (`UserRole`). The spec's "DEVELOPER_ADMIN" means `DEVELOPER`.
- No Claude/AI attribution in commits or PRs (repo `CLAUDE.md`).
- Update `docs/status.md` (WS10a row, Next up, Last updated) and `docs/known-issues.md` (LLM cost now charged; `LedgerEntryType.REVERSAL/FEE` still unused; dual-write) in the final task.
- Backend tests (Colima needs the socket override): `cd backend && TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock mvn test -Dtest=<ClassName>[,<ClassName>]` (Maven, `pom.xml`). Below, "Run `X`" means this command with `-Dtest=X`; a package means `-Dtest="com.agentstore.platform.<pkg>.**"`.

## Review Focus

1. **Fee rounding leaves a paisa unaccounted.** ₹0.01 or ₹33.33 charged at 20%: postings must still sum to zero, developer gets the remainder. Test in Task 4.
2. **Two runs of the same buyer charging at the same moment.** Balances must equal the sum of postings and no deadlock occurs. Concurrency test in Task 4.
3. **A wallet that existed before WS10a** (balance ₹10,000, no ledger account): first charge must leave `BUYER_WALLET` = 10,000 − charge, not −charge. Test in Task 2.
4. **A sandbox run (no connection)** must post nothing; a BYOK/MOCK/REPLAY LLM call must not be deducted. Tests in Tasks 4 and 5.
5. **An org switched to postpaid while its wallet holds money** is refused with 409; a postpaid org with no wallet row can still start runs. Tests in Task 6.
